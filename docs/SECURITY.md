# 安全审计说明

## 1. 本设计在隐私保护层面的优势

1. **零知识服务器**：后端代码中不存在任何解密逻辑与密钥材料；数据库 `blobs.cipher` 字段全为 AES-256-GCM 密文。即使服务器被完全攻破、数据库被拖走，攻击者得到的也只有随机字节。
2. **密钥不出设备**：主密码经 PBKDF2（310000 轮）派生为不可导出的 `CryptoKey`，仅存在于设备内存；关闭标签页/锁定金库即随内存释放。主密码、密钥从不经过网络。
3. **认证加密防篡改**：AES-GCM 自带完整性校验，任何密文被篡改都会解密失败，无法静默替换数据。
4. **传输层加密**：生产部署务必在反代（Caddy/Nginx）配置 HTTPS，所有 API 流量 TLS 加密。
5. **备份同样加密**：WebDAV 备份文件在客户端加密后才出设备，WebDAV 服务商与中继服务器均不可读。
6. **合规边界**：谷歌 OAuth 仅按官方文档做身份验证，本软件不涉及、也不提供任何规避网络管理的方法；部署者在中国境内使用谷歌服务需自行遵守中国相关法律法规。

## 2. 需要注意的风险点（务必阅读）

### 高风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| **主密码丢失** | 无任何找回手段，数据永久丢失 | 务必牢记主密码；可另行手抄保存于物理安全场所 |
| **主密码强度** | 弱密码可被离线暴力破解（服务器存有 Verifier，可被用于离线尝试） | 强制使用长密码（建议 12 位以上混合）；演进路线见下文 Argon2id |
| **恶意/被篡改的前端代码** | 若服务器被攻破且向浏览器推送被篡改的 JS，可在用户输入主密码时窃取 | 服务器本身只存密文意义仍在；更严谨做法是对前端做子资源完整性（SRI）/代码签名，或本地构建后部署 |
| **设备失窃（已解锁状态）** | IndexedDB 中有明文缓存 | 移动端启用系统级锁屏；网页端用完点「锁定金库」；后续可加本地缓存加密 |

### 中风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| 同步冲突 last-write-wins | 极端并发编辑可能丢最后几笔 | 单人多设备场景影响有限；演进为块级 CRDT |
| 无速率限制 | 当前 API 未做登录限速，可被暴力撞库（会话令牌本身安全） | 生产环境在反代层加 fail2ban/限速；或后续内置限速中间件 |
| 开发模式登录 | `ALLOW_DEV_AUTH=1` 时任何人可用任意邮箱登录（仍需主密码才能读数据） | **生产环境必须为 0** |
| 元数据可见性 | 服务器可见 blob 数量、大小、修改频率 | 属零知识系统的固有边界；可对密文填充对齐以缩小指纹 |

### 演进路线（生产加固建议）

1. KDF 从 PBKDF2 升级为 **Argon2id**（抗 GPU/ASIC 暴力破解，需 WASM 实现）；
2. 启用 HTTPS + HSTS（Caddy 反代一行配置）；
3. 前端资源加 SRI 哈希；考虑引入 Content-Security-Policy 禁止内联脚本；
4. 谷歌 OAuth 改用 `jose` 库本地校验 JWKS 签名（当前 tokeninfo 端点依赖额外一次外网请求）；
5. 增加登录限速与会话管理（列出/吊销设备）；
6. 二次验证（TOTP）作为可选层。

## 3. 隐私承诺清单（代码可验证）

- ✅ `server/` 目录中不存在 `decrypt`、密钥管理或任何明文笔记处理逻辑
- ✅ 数据库中除 email（OAuth 身份）外，无任何用户内容字段为明文
- ✅ 前端加密发生在 `crypto.js`/`webdav.js`，全部调用 WebCrypto 本地 API
- ✅ WebDAV 凭据仅存浏览器 localStorage，服务器不落库
